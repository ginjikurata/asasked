# AsAsked: сверка намерения с корзиной

Файл прочитан Claude Code при открытии проекта. Здесь контекст, чтобы не
пересказывать историю заново.

Рабочее название продукта — **AsAsked** (решено 2026-10-25). С 2026-10-26
в центре продукта — **страж перед оплатой** (guard.py): не дать агенту купить
не то, а не разбирать ошибку после. Проверка постфактум — только для споров
и подсчётов в бенчмарке. Формат — открытый эталон для индустрии: библиотека,
песочница, бенчмарк «без стража / со стражем», сайт asasked.dev (позже). Раньше проект
назывался concord, но Concord теперь имя студии, внутри которой AsAsked —
второй продукт. До публичного запуска продукт не раскрывается.

## О чём проект

Когда ИИ-агент покупает что-то за человека, платёжный стандарт Verifiable
Intent (Mastercard + Google, черновик v0.1) криптографически доказывает, что
агент не вышел за формальные рамки: артикул из утверждённого списка, сумма в
коридоре, продавец разрешённый.

Он **не проверяет**, совпадает ли купленное с тем, что человек имел в виду.
Просьба человека лежит в мандате полем `prompt_summary` — свободным текстом,
необязательным, помеченным «для журнала аудита». Ничто не сверяет его ни с
ограничениями, ни с итоговой корзиной.

При этом в обсуждении ответственности (issue #15) вину возлагают на магазин:
«магазин несёт ответственность, поскольку он сверил корзину с намерением
пользователя». Обязанность назначена, инструмента для неё не существует.

ВАЖНО — атрибуция этой цитаты ошибочно указывалась здесь ДВАЖДЫ, не
повторять ни одну из ошибок. Проверено по тексту issue 2026-09-26:

- Issue #15 написал `urzatwister` (без связи с репозиторием) — одна из
  серии «Ant …» (#12–17; #13 называется «Ant Financial - Trust Model»).
- В теле issue идут вопросы, затем «Answers: @fahads9 please verify» и
  ответ с пометкой **[CY]**: «The merchant is liable…». Ответ кончается
  фразой «We are working on the liability shift for the Agent Pay Acceptance
  framework».
- `@fahads9` цитату НЕ писал — его попросили её подтвердить. Комментариев
  в issue ноль: подтверждения не было.
- Кто такой [CY] — неизвестно, и гадать об этом не нужно.
- Ошибка №1 (в этом файле): «сопровождающий стандарта сказал». Ошибка №2
  (моя правка месяц назад, по пересказу WebFetch): «участник @fahads9
  написал». Обе неверны. Урок: цитаты проверять по исходному тексту через
  API, а не по пересказу страницы.

Правильная формулировка — «ответ, зафиксированный в #15, не подтверждён,
официальной позицией не является». Позиция всё равно показательная:
сверять корзину с намерением кто-то должен, и магазин — очевидный кандидат.

Проект закрывает этот разрыв.

## Что уже проверено

- Спецификация скачана, примеры запускаются. ~3 150 строк Python, одна
  внешняя зависимость (`cryptography`).
- Построен прототип: 8 сценариев покупки, каждый с настоящей
  криптографической цепочкой VI. **В 6 из 8 стандарт пропускает покупку,
  расходящуюся с просьбой человека.**
- Расхождения, которые стандарт не видит: подмена бренда, не тот цвет и
  размер, количество по пределу вместо просьбы, невозвратный товар при
  просьбе «чтобы можно было вернуть», срок доставки мимо дедлайна, верх
  ценового коридора при просьбе «недорого».
- Контрольные случаи ведут себя правильно: честная покупка проходит обе
  проверки; грубое нарушение (артикул вне списка) стандарт ловит сам.
- Первая задача выполнена: `extract_intent` подключён к настоящей модели
  (Gemini). Прогнан на 37 живых разговорных фразах — путаных, с оговорками,
  с «ну ты понял», с противоречиями внутри одной фразы. После одной правки
  промпта (нормализация транслитерированных названий брендов, «Асиксы» →
  «ASICS») — 0 сбоев извлечения, все проверяемые поля совпали с ожиданием.
- Извлечение выдерживает живую речь на смысловом уровне, но у самой схемы
  `IntentFacts` нет способа выразить «это не принципиально» или «примерно».
  На «недорого, но если увидишь супер вариант чуть дороже — бери» модель
  всё равно вернула жёсткое `price_preference=cheap`; на «рублей на триста
  где-то, плюс-минус» — точное `explicit_max_cents=30000`, которое сверка
  трактует как жёсткий потолок. Это не сбой модели, а отдельная дыра в
  схеме фактов — не там же, где дыра в самом стандарте VI, но того же рода:
  теряется именно то, что не влезает в структурированное поле.
- Эта дыра в схеме закрыта: модель дополнительно отдаёт `soft_fields` —
  какие из фактов человек сам обозначил как необязательные. Сверка на
  таких полях выдаёт предупреждение вместо блокировки (использован уже
  существовавший, но раньше не задействованный уровень `WARN`). Проверено
  end-to-end: «чёрные кроссовки, а вообще если белые — не принципиально» +
  покупка белых кроссовок теперь даёт `coherent=True` с пометкой, а не
  расхождение.

## Устройство прототипа

```

  catalog.py          товары с атрибутами, которых нет в ограничениях VI
  scenarios.py        8 сценариев: просьба → ограничения → покупка
  vi_runner.py        строит настоящую цепочку VI и проверяет её SDK Mastercard
  guard.py            страж перед оплатой: proceed / ask + готовый вопрос человеку
  mcp_server.py       тот же страж как MCP-сервер (asasked-mcp, инструмент check_order)
  integrations/       страж перед инструментом оплаты: Claude Agent SDK, OpenAI Agents SDK, LangChain
  coherence.py        извлечение (делегирует в llm_extract.py) + детерминированная сверка
  llm_extract.py      вызов языковой модели (Gemini или Claude) — единственное место с ИИ
  stress_phrases.py   37 живых фраз на прочность extract_intent
  stress_phrases_en.py  40 английских фраз тех же категорий
scripts/
  run_stress_test.py  прогон стресс-наборов (--lang ru|en|all, --provider gemini|anthropic|both)
  run.py              прогон 8 сценариев (постфактум: покупка уже сделана)
  run_prepurchase.py  прогон тех же сценариев в режиме «до покупки»
  build_conformance_vectors.py  генерирует conformance_vectors.json (не в git)
  store/            песочница-магазин: catalog_v1.py (каталог из семейств,
                    ловушки по построению), store.py (сессия, инструменты
                    агента, заказ через VI), http.py (то же по HTTP)
  harness/          прогоны агентов: tasks.py (наборы pilot и hard с
                    разметкой — оценка по ней, не по движку), agent.py (цикл
                    Claude и OpenAI-совместимых), user_sim.py (симулятор
                    человека для ask_user), run.py (оценка и запись)
  harness/labels.py    разметка как данные (какие товары, сколько, предел, «ничего»)
  harness/dataset.py   датасет v1: 13 шаблонов ловушек → 200 задач, 100 open / 100 hidden
data/tasks_v1.jsonl     открытая половина датасета. Скрытая — вне репозитория, в
                        ../hidden (или ASASKED_HIDDEN_DIR), с теми же именами файлов,
                        что в data/; её НЕ публиковать и в репозиторий не класть
data/review_v1_cos.csv  таблица разметки (ok / fix / drop); размечает один человек
                        по смыслу — английские задачи через перевод (review_v1_cos.xlsx)
data/review_v1_templates.csv      проверка остальных шаблонов вопросом «что правильно купить»
data/review_v1_translation_ru.csv  перевод задач моделью (scripts/translate_review.py)
data/naturalness_v1_model.csv     естественность английского — проверка моделью
scripts/build_dataset.py  сборка датасета и таблиц; --agreement a.csv b.csv
scripts/run_agents.py   реальные модели покупают в магазине → runs/*.jsonl
scripts/demo_store.py   наивный агент в магазине — без модели
scripts/serve_store.py  магазин по HTTP на localhost
tests/              pytest: сверка, цепочка VI, магазин — без модели и сети
(черновики писем — вне репозитория, в ../drafts)
site/               сайт asasked.dev (Next.js, как у Concord); до запуска noindex
README.md           описание проекта на английском — для тех, кто придёт
                    со стороны стандарта. Все цифры в нём сверены с кодом;
                    менять их только вместе с кодом.
```

Принципиальное разделение в `coherence.py`:

1. **Извлечение** — превратить слова человека в факты. Только здесь нужна
   языковая модель (`llm_extract.py`).
2. **Сверка** — сравнить факты с корзиной. Обычный детерминированный код.

Разделение не косметическое: заключение «так решил ИИ» в споре ничего не
стоит, а «человек просил возврат, товар невозвратный» — стоит, потому что
проверяется вручную. Сохранять это разделение при любых изменениях.

## Первая задача (выполнена)

Заменить заглушку `extract_intent` в `coherence.py` на настоящую языковую
модель и проверить, выдерживает ли она живую речь.

Главная неизвестность проекта была: **насколько надёжно модель вытаскивает
намерение из живой речи.** Ответ по итогам 37 фраз — да, на уровне смысла
выдерживает; не выдерживает схема фактов там, где в просьбе есть оттенок
(«не принципиально», «примерно») — см. «Что уже проверено». Модель — Gemini,
ключ в `.env` (в репозиторий не попадает), провайдер выбран потому, что даёт
бесплатный доступ без карты; свежие top-tier модели там сидят на очень
жёсткой бесплатной квоте (5 запросов в минуту / 20 в день) — для массовых
прогонов лучше подходит `-flash-lite-latest` уровень.

## Особенности AnyModel (ключ моделей)

- Claude: CLAUDE_BASE_URL=https://anymodel.org/v1, модель без префикса
  (claude-sonnet-5). Свои имена CLAUDE_*, потому что ANTHROPIC_BASE_URL
  часто уже задан в окружении и перебивает .env.
- Остальные модели — OPENAI_COMPAT_* на тот же адрес; список: GET /v1/models.
- Cloudflare режет User-Agent Python-urllib (ошибка 1010) — нужен свой.
- Иногда отвечает 200 с {"error": ...} внутри — повторять.
- Пустой вызов инструмента (без аргументов) роняет ответ вышестоящего
  провайдера, поэтому у checkout и view_cart обязательные аргументы.
- Gemini через AnyModel для агентов не годится: вызовы инструментов
  теряются (уходят текстом в reasoning_content). Для извлечения — годится.
- AnyModel портит «__» в именах инструментов: отдают `mcp__shop__search`,
  модель вызывает `mcp_shop_search`. Поэтому MCP-инструменты в Claude Agent
  SDK через AnyModel не работают; живая проверка крючка шла на встроенном
  Write (проверено 2026-10-31).

## Правила работы

- Этот файл лежит в репозитории и будет публичным вместе с ним. Не писать

  Не менять её файлы у себя — работать поверх.
