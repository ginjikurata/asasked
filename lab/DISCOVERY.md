# Автоматический поиск магазинов с крипто-оплатой: набросок

Записано 2026-11-19. Первая версия кода: `scripts/discover.mjs` (2026-11-20). Запуск по расписанию и публикация результатов только после «да» владельца.

Запуск вручную:

```
node scripts/discover.mjs bitpay            # новые кандидаты из справочника BitPay
node scripts/discover.mjs coingate          # новые кандидаты из списка CoinGate (Online Stores, Pay Direct)
node scripts/discover.mjs domain a.com b.com # проверить конкретные сайты
node scripts/discover.mjs known             # прогон по уже размеченным магазинам (проверка точности)
node scripts/discover.mjs recheck           # ежемесячная перепроверка магазинов из каталога -> research/recheck.csv
```

Результат по умолчанию пишется в `research/candidates.csv` (`--out` меняет путь, `--limit N` ограничивает число сайтов).
Колонка `result`: `strong`, `weak`, `none`, `negative` (магазин прямо пишет, что крипту не берёт), `blocked`, `error`.

## Что делает

Программа раз в неделю:

1. собирает **кандидатов** из открытых источников;
2. заходит на главную страницу и страницу оплаты кандидата и ищет **признаки крипто-оплаты**;
3. записывает найденное с доказательством (какой признак, на какой странице, когда) в `research/candidates.csv`.

Человек просматривает новых кандидатов, как сейчас: открывает ссылку-доказательство и ставит `yes`.
Только после этого магазин уходит в `research/merchants.csv` и на сайт. Сама программа на сайт ничего не пишет.

## Откуда брать кандидатов

| Источник | Что даёт | Уже проверено |
|---|---|---|
| Справочник BitPay (sitemap bitpay.com/directory) | ~265 записей, новые появляются в sitemap | да, 18.11 разобран вручную |
| Список магазинов CoinGate (coingate.com/stores, категория Online Stores) | ~31 магазин с меткой Pay Direct, домен магазина | да, 20.11, режим `coingate`; robots разрешает /stores; в каталог пока не идут (см. ниже) |
| Глобальный каталог Shopify (UCP) | продавцы по категориям товаров, их домены | 20.11: для USDC бесполезен, Shopify USDC в UCP не виден, фильтра по оплате нет |
| Объявления шлюзов и блоги (Shopify USDC, Helio, Coinbase Commerce) | свежие магазины, о которых пишут | вручную, источник `announcement` |
| Веб-поиск по фразам «pay with crypto», «we accept USDC» и т. п. | длинный хвост | нет |

Справочник BitPay сам отличает подарочные карты от прямой оплаты: заголовок «Buy X Gift Cards» в каталог
магазинов не идёт, «Pay with … at X» идёт. У CoinGate так же: берём только карточки «Pay Direct», а карточки
«Gift Cards» (ссылки на /gift-cards/) это CoinGate продаёт подарочную карту, магазин крипту не берёт.

Про CoinGate важно:

- Страница 1 категории ссылается на страницы до 5, но 4 и 5 отвечают 404 (ноябрь 2026). Скрипт читает,
  пока страницы отвечают 200.
- Сам CoinGate принимает USDC в сети Solana (список валют на coingate.com/supported-currencies, проверено 20.11).
  Но каждый магазин сам выбирает монеты, а список магазинов этого не показывает: на странице магазина написано,
  что он может принимать не все.
- Многие такие магазины показывают CoinGate только внутри оформления заказа, поэтому проверка сайта часто даёт `none`.
  Сам факт листинга помечен в колонке `gateway` как `CoinGate (listed)`; человек проверяет, есть ли USDC на Solana.
- **CoinGate отложен (20.11).** Оплата идёт через счёт CoinGate на pay.coingate.com, а помощник в браузере
  умеет проверять только счёт BitPay. Счёт BitPay читается открыто, без ключей: в нём видны название магазина,
  сеть, сумма и адрес. У CoinGate такого открытого способа нет. По документации данные счёта (сумма, адрес)
  выдаются только по ключу магазина. Сайт pay.coingate.com в robots.txt закрыт для всех ботов, кроме превью ссылок.
  Без ключа открыт только запрос на возврат по номеру счёта, а суммы и адреса оплаты в нём нет.
- Остаётся один путь: помощник читает открытый счёт в браузере самого человека, это не обход сайта ботом.
  Как устроена эта страница, неизвестно: её разметка нигде не описана. Чтобы сделать такую проверку, нужен
  один настоящий счёт, который откроет владелец (без оплаты), или тестовый счёт CoinGate (sandbox.coingate.com,
  нужна учётная запись, решает владелец; монет там меньше, Solana может не быть).
- Пока проверки счёта CoinGate нет, такие магазины в каталог не идут. Кандидаты остаются в `research/candidates.csv`.

Не используем (по их же условиям): Cryptwerk (только личный некоммерческий просмотр) и SpendCrypto (запрещён
автоматический сбор, кроме их API). Cryptowisser: страница условий не найдена, robots закрывает адреса с `?`,
пока не трогаем. Справочник BTCPay: в основном Bitcoin, не USDC.

## Признаки крипто-оплаты на сайте магазина

- Shopify USDC: иконка `pi-usdc` в подвале (уже подтверждено на трёх магазинах).
- Скрипты и ссылки шлюзов в коде страницы: `bitpay.com`, `commerce.coinbase.com`, `nowpayments.io`,
  `coingate.com`, `triple-a.io`, `hel.io`, `confirmo.net`.
- Страница вида `/pay-with-bitcoin`, `/crypto` или упоминание оплаты криптой в FAQ.

Один слабый признак (только текст) даёт статус «частично», сильный (иконка кассы или скрипт шлюза) даёт кандидата
на `yes`. Окончательный `yes` ставит человек.

## Правила обхода

- Честный User-Agent с адресом проекта, соблюдаем robots.txt, не чаще одного запроса в несколько секунд на сайт.
- Только публичные страницы: главная, страница оплаты, FAQ. Корзину и оформление не трогаем.
- Ответ 403, 429, капча или страница защиты от ботов: магазин помечаем `blocked` и пропускаем. Ничего не обходим,
  прокси и «невидимые» браузеры не используем.

## Перепроверка опубликованных

Раз в месяц те же проверки идут по магазинам из каталога. Если признак пропал два раза подряд, магазин
помечается к ручной проверке и до неё скрывается с сайта. Дата `checked` на сайте обновляется только после
успешной проверки.

Сделано 20.11: `node scripts/discover.mjs recheck`. Проверяет все строки `yes` из `research/merchants.csv`
по тем же правилам обхода. Состояние пишется в `research/recheck.csv`, по строке на магазин:

| Колонка | Что значит |
|---|---|
| `seen` | самый сильный признак, который бот когда-либо видел на сайте (`strong` или `weak`); пусто, если не видел ни разу |
| `last_ok` | дата последнего прогона, где признак был не слабее `seen`; по ней на сайте двигается `checked` |
| `misses` | сколько прогонов подряд бот открыл сайт, но такого признака не нашёл |
| `status` | `ok`; `review` (скрыт с сайта до ручной проверки); `manual` (бот признака здесь не видит, например крипта только в оформлении заказа: такой магазин не судим и не скрываем, дату не двигаем) |

Что считается промахом:

- признака нет, хотя раньше был; или признак слабее прежнего (был `strong`, стал `weak`);
- магазин прямо пишет, что крипту не берёт (`negative`), даже если раньше бот признака не видел.

`blocked`, `error` и запрет в robots промахом не считаются: бот просто не смог посмотреть, всё остаётся как было.
Два промаха подряд дают `review`. `npm run data` (и сборка сайта) такой магазин не показывает и пишет его в вывод.

Как снять `review` после ручной проверки:

- магазин всё ещё берёт крипту: удалить его строку из `recheck.csv`, следующий прогон начнёт заново;
- больше не берёт: поставить `no` в `merchants.csv`, строка из `recheck.csv` уйдёт сама.

Первый прогон только запоминает, что бот видит сейчас. Скрывать магазины начнут следующие ежемесячные прогоны.
После прогона нужно пересобрать и выложить сайт, иначе на сайте ничего не поменяется (выкладка только по «да» владельца).

### Запуск раз в месяц на этом Mac (launchd)

`scripts/recheck-monthly.sh` запускает `node scripts/discover.mjs recheck`, пишет лог в
`research/recheck-logs/ГГГГ-ММ-ДД.log` и показывает уведомление macOS с итогом. Сайт он не собирает и не выкладывает.
Расписание лежит в `scripts/dev.asasked.lab.recheck.plist`: 1-е число каждого месяца в 10:00. Если Mac в это время
спит, запуск будет после пробуждения. Если выключен, запуск этого месяца пропадёт.

Ставит владелец, из Терминала:

```
cp "/path/to/AsAsked/lab/scripts/dev.asasked.lab.recheck.plist" ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.asasked.lab.recheck.plist
launchctl print gui/$(id -u)/dev.asasked.lab.recheck     # проверить, что задача стоит
```

Убрать:

```
launchctl bootout gui/$(id -u)/dev.asasked.lab.recheck
rm ~/Library/LaunchAgents/dev.asasked.lab.recheck.plist
```

Запустить вручную, не дожидаясь 1-го числа: `launchctl kickstart gui/$(id -u)/dev.asasked.lab.recheck`
(или `sh scripts/recheck-monthly.sh` из lab). После правки plist: `bootout`, снова `cp` и `bootstrap`.
Ошибки самого запуска пишутся в `research/recheck-logs/launchd.log`.

После уведомления: если что-то скрыто, человек проверяет эти магазины (см. выше), потом сборка и выкладка по «да».
